# FIN-P2-R：R 轨道 Risk Evidence

## 1. 定位

`FIN-P2-R` 是 Phase 2 的风险辅助证据轨道。它只生成财务报告复核优先级，
不替代 M 轨道的因子有效性主证据，也不构成造假、错报、无风险、因子准入或交易
结论。

当前实现只接受标记为 `synthetic_test_only=true` 的确定性合成记录。真实监管事实
核验、原始公告抓取、生产持久化及任务 8 交接均不在本任务范围。

## 2. 两层协议

第一层为透明会计红旗，按冻结规则加分：

| 红旗 | 分值 | 约束 |
|---|---:|---|
| 非金融公司资产负债率大于 85% | 12 | 银行、券商、保险不使用该阈值 |
| `(净利润-经营现金流)/总资产 > 8%` | 18 | 缺失值不补零 |
| 净利润为负且经营现金流为正 | 18 | 只提示检查构成 |
| 应收、存货、其他应收异常 | 各 12 | 输入为显式异常标记 |
| 非经常损益或资产异常 | 12 | 输入为显式异常标记 |
| 非标准审计意见 | 25 | 证据中保留意见类型 |
| 重述或更正 | 15 | 只作为复核证据 |

复核等级固定为：`strong_warning >= 60`、`warning 35-59`、
`review 15-34`、`low < 15`。Top-K 队列先按透明分数降序，再按公司和报告期
稳定排序，不利用标签改变排序。

第二层是可选的一维 Logistic 校准模型。它只使用训练公司中时点已可见的
`hard_positive` 与 `confirmed_negative`，输入特征仅为透明分数。公司分组由
`split_salt + symbol` 的 SHA-256 决定，因而同一公司不会跨训练集和测试集，且
切分与标签无关。

## 3. 标签治理

标签严格分为：

- `hard_positive`：有时点、来源和质量字段的正式强标签；
- `soft_positive`：弱监督或待复核正向信号；
- `confirmed_negative`：只能来自显式、可追溯的负标签；
- `unlabeled`：未知，永不转为负例。

只有 `label_available_at <= as_of` 的标签可进入有效标签层。未来才可见的标签在
本次运行中降为 `unlabeled` 并产生审计 warning；它不会被当作
`confirmed_negative`。财务记录本身若在 `as_of` 后才公告，则整批 fail closed。

若有效 `hard_positive` 公司少于 10 家，监督层返回 `not_run`，PR-AUC、
ROC-AUC、Brier、Top-K 命中率和校准指标均为空；透明描述和人工复核队列仍保留。
训练或测试公司切分缺少任一类别时也使用相同的 `not_run` 语义。

## 4. 指标与审计

监督层完成时报告：

- PR-AUC（average precision）；
- ROC-AUC；
- Brier score；
- 测试集 Top-K 命中率；
- 五箱校准明细及 expected calibration error。
- 按公司报告期稳定哈希置换测试标签的负向对照 PR-AUC 与 ROC-AUC。

审计对象包括配置、原始输入、财务字段、标签字段、公司切分、输出和各记录内容
的 SHA-256。输入在执行前后重新指纹化，输出按公司和报告期规范排序，保证同一
语义输入可复现。

结构化失败状态覆盖：配置错误、记录结构错误、重复公司报告期、未来公告、非法
标签、标签来源缺失、非有限数值、非合成输入和输入突变。

## 5. 使用边界

输出中的 `strong_warning / warning / review / low` 只表达人工复核优先级。
高优先级案例仍需回到原始公告、问询函、审计意见、监管文件和更正材料核验。
合同或收入真实性还需要关系、票税、物流/验收和银行资金闭环等外部证据。

本模块不提供交易指令，不依据“当前没有监管行动”推断无风险，也不得把模型概率
解释为造假或错报事实。
